## Started dev server; documented a non-obvious sandbox gotcha

**`vite --host 0.0.0.0` HANGS in this environment — it does not error, it just
produces no output and never binds.** `npm run dev` (which is
`vite --host 0.0.0.0`) therefore appears to hang. The earlier symptom was
`Error: The service was stopped: write EPIPE` from esbuild while loading
`vite.config.ts`, which is a red herring.

Working invocation:
```
nohup npx vite --host 127.0.0.1 --port 5199 > /tmp/v.log 2>&1 &
```
Binds fine, HTTP 200. **Use `127.0.0.1`, not `0.0.0.0`.**

Also: running the dev server via `run_in_background` with `2>&1` piped produced
no output and no listener. Launching it inside a single shell with `nohup` +
file redirect, then verifying with `netstat | grep <port>` and `curl`, works.
Always verify the port directly — do not trust the log or the task status.

- `/` → `pages/Home.tsx` — 7 sections in order: Hero, Work, Approach,
  Services, About, Testimonials, Contact.
- `/case-study/:slug` → `pages/CaseStudy.tsx` — 6 blocks: Header (client/role/

Nav (`components/Nav.tsx`) and Footer both link exactly those 5 ids.

## Finding: Testimonials section has no `id` and is absent from nav

`sections/Testimonials.tsx` renders `<section className=...>` with **no `id`**,
while the other five anchored sections all have one. So it cannot be deep-linked
and it appears in neither the Nav nor the Footer link lists. Also its
`SectionHeading` label ("Testimonials") has no matching nav entry. Inconsistent
with the other sections — worth an `id="testimonials"` + nav entry if the section
should be reachable.
