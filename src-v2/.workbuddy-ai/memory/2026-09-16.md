## Started dev server; documented a non-obvious sandbox gotcha

**`vite --host 0.0.0.0` HANGS in this environment — it does not error, it just
produces no output and never binds.** `npm run dev` (which is
`vite --host 0.0.0.0`) therefore appears to hang. The earlier symptom was
`Error: The service was stopped: write EPIPE` from esbuild while loading
`vite.config.ts`, which is a red herring.

Working invocation:
```
nohup npx vite --host 127.0.0.1 --port 5199 > /tmp/v.log 2>&1 &
```
Binds fine, HTTP 200. **Use `127.0.0.1`, not `0.0.0.0`.**

Also: running the dev server via `run_in_background` with `2>&1` piped produced
no output and no listener. Launching it inside a single shell with `nohup` +
file redirect, then verifying with `netstat | grep <port>` and `curl`, works.
Always verify the port directly — do not trust the log or the task status.

## Enumerated the app structure (requested)

Two routes (`HashRouter`):
- `/` → `pages/Home.tsx` — 7 sections in order: Hero, Work, Approach,
  Services, About, Testimonials, Contact.
- `/case-study/:slug` → `pages/CaseStudy.tsx` — 6 blocks: Header (client/role/
  timeline/stack grid), Cover, Narrative (sticky Overview sidebar + details
  lead-in + Context + The problem + Process + Solution), Gallery, Outcomes,
  Testimonial, Next project.
- `*` → falls back to Home.

Section anchors present: `#work`, `#approach`, `#services`, `#about`, `#contact`.
Nav (`components/Nav.tsx`) and Footer both link exactly those 5 ids.

## Finding: Testimonials section has no `id` and is absent from nav

`sections/Testimonials.tsx` renders `<section className=...>` with **no `id`**,
while the other five anchored sections all have one. So it cannot be deep-linked
and it appears in neither the Nav nor the Footer link lists. Also its
`SectionHeading` label ("Testimonials") has no matching nav entry. Inconsistent
with the other sections — worth an `id="testimonials"` + nav entry if the section
should be reachable.

## Finding: Testimonials copy cites companies that do not exist in the project roster

- `data/site.ts` testimonials are attributed to **Pulse, Atlas, Waveform**.
- `data/projects.ts` clients are **Nairaflow, Kobo, Ajo, Owo** — none of which
  appear in the testimonials.
- The asset filenames (`pulse.svg`, `atlas.svg`, `nomad.svg`, `waveform.svg`)
  show the projects were renamed from an earlier Pulse/Atlas/Nomad/Waveform scheme.
  The standalone Testimonials section was never updated to match.

Note the case-study pages are internally consistent — each project carries its
own correctly-matched testimonial (Chiamaka Obi/Nairaflow, Emeka Eze/Kobo,
Funmi Adeyemi/Ajo, Derin Ajayi/Owo). Only the standalone section is stale.

Not fixed — this is copy/attribution content, the user's call. Flagged only.

## Both findings FIXED (commit `9bf621a`)

### 1. Testimonials now reachable
- Added `id="testimonials"` + `scroll-mt-24` to `sections/Testimonials.tsx`,
  matching the sibling sections.
- Added `{ id: 'testimonials', label: 'Testimonials' }` to Nav `links` (after
  About) and `'testimonials'` to the Footer id array.
- **Nav breakpoint moved `md` → `lg`** (3 places: desktop nav `hidden lg:flex`,
  hamburger `lg:hidden`, mobile panel `lg:hidden`). Reason: 6 links + logo + CTA
  overflow at 768px. gap-8 → gap-7. Screens 768–1023px now get the hamburger.
  If a 7th link is added, re-check this.

### 2. Duplicated stale quotes eliminated at the source
Key discovery: **all three `site.ts` quotes were verbatim duplicates of the
per-project quotes** — same text, different (wrong) author and company. So the
fix was not to correct the copies but to delete the duplication:
- `sections/Testimonials.tsx` now maps over `projects` and renders
  `p.testimonial.{quote,author,role}`; `key={p.slug}`.
- Removed the `testimonials` array from `data/site.ts` — including the `rating`
  field, which was **never rendered anywhere** (another dead field).
- Side effect: 4 quotes now render instead of 3 (Ajo was previously omitted —
  only 3 of 4 projects were represented).
- Grid changed `md:grid-cols-3` → `sm:grid-cols-2 lg:grid-cols-4` for even layout.

Verification: bundle contains Chiamaka Obi / Emeka Eze / Funmi Adeyemi /
Derin Ajayi (1 each) and **zero** occurrences of Maya Lindqvist / Daniel Okafor /
Sofia Marchetti / "VP Product, Pulse" / "Engineering, Atlas" / "Founder, Waveform".

`npm run verify` → exit 0. Working tree clean.

### Lesson worth keeping
This was the third instance of the same root cause in this codebase: **two things
claiming to be authoritative** (v1 vs v2 source trees; tsconfig vs index.html;
site.ts testimonials vs projects.ts testimonials). Each produced silent drift.
The generalizable rule: derive, don't duplicate.
